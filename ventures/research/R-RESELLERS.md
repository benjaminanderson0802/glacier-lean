# R-RESELLERS: low-capital reseller tools

**Research date:** 2026-10-10
**Owner context:** Benjamin Anderson, Anderson Education LLC; existing Apify, Shopify Partner, Jobber developer, and Chrome Web Store accounts; Glacier/Codex/Claude available.
**Scope:** Software for e-commerce resellers and small marketplace/store sellers. No implementation or paid-service commitment is included here.

## Drift check and acceptance

- **Checkpoint:** PH12.10, Apify data tools, with findings also useful to PH12.22 integration/audit. This is market research supporting those in-scope venture tasks; it does not add a venture checkpoint or mark one complete.
- **Dependencies:** PH12 depends on PH5 and PH9, both still in progress. The owner-authorized PH12 wave allows assigned venture work to start before exit, but no completion claim follows from this research.
- **Properties/metrics:** P-LOOPS and P-CONTROL, with P-VERIFY for source-linked outputs; relevant measures are M-SURVIVE, M-INTERVENE, M-VERIFIED, and M-COST.
- **Existing-tool check (I-01):** Prefer official platform APIs, seller exports, government data, and existing marketplace channels. Do not duplicate seller platform features where they cover the need. The shortlist below leans toward narrow reconciliation/alert jobs and public-record data products.
- **Acceptance:** 8–12 candidate ideas, a transparent scored top three, 5-step launch plan for each, and explicit terms/legal red flags, with primary URLs for factual claims.

## What the evidence does and does not say

U.S. retail e-commerce was estimated at $340.2 billion in Q2 2026, 17.1% of total retail sales; Etsy reported 5.6 million active Etsy sellers and 86.5 million active buyers at year-end 2025. These figures establish a large addressable seller ecosystem, not demand or willingness to pay for any proposed tool. [U.S. Census Bureau, Q2 2026](https://www.census.gov/retail/ecommerce.html); [Etsy 2025 Form 10-K](https://investors.etsy.com/sec-filings/all-sec-filings/content/0001370637-26-000019/etsy-20251231.htm)

Platform APIs make several problems technically addressable without scraping. Shopify's Admin GraphQL API supports merchant-authorized store data with scoped permissions; its refund data supports reports on refund amounts/reasons. Amazon's SP-API supports seller-authorized reports and fee estimates, while warning that estimated fees are not guaranteed. [Shopify API overview](https://shopify.dev/docs/apps/build/apis); [Shopify refund query](https://shopify.dev/docs/api/admin-graphql/latest/queries/refund); [Amazon SP-API onboarding](https://developer-docs.amazon.com/sp-api/docs/onboarding-overview); [Amazon fee estimate tutorial](https://developer-docs.amazon.com/sp-api/docs/get-product-fee-estimates-asin); [Amazon fee estimate caveat](https://developer-docs.amazon.com/sp-api/docs/notification-type-values)

Marketplaces are already crowded in broad categories. Shopify's App Store currently lists hundreds of returns/exchanges apps; the profit reporting category also includes paid offerings. These are directional competition checks, not a complete census and not proof a narrower segment is saturated. [Shopify returns category](https://apps.shopify.com/categories/orders-and-shipping-returns-and-warranty-returns-and-exchanges/all); [Profit Calc listing](https://apps.shopify.com/profit-calc)

## Candidate ideas (10)

1. **Amazon FBA fee and margin variance monitor (SP-API/report upload).** Compare seller-entered landed cost and expected fee estimate with actual settlement/report line items; flag SKUs whose contribution margin changed. Start CSV-first, then authorized SP-API reports. Amazon exposes fee estimates and reports, but calls the estimate non-guaranteed. Competition is strong in general profit analytics, so differentiate on a simple “what changed / evidence” exception digest. [Amazon fee estimates](https://developer-docs.amazon.com/sp-api/docs/get-product-fee-estimates-asin); [Amazon reports use cases](https://developer-docs.amazon.com/sp-api/lang-it_IT/docs/reports-api-v2021-06-30-use-case-guide); [Profitability app example](https://apps.shopify.com/profit-calc)
2. **Amazon FBA inventory and stranded-listing exception digest.** Turn seller-authorized inventory/listing reports into a daily “stale, stranded, low-stock” exception list, with links to Seller Central and no automatic listing edits. SP-API includes inventory/catalog/report workflows; Amazon app registration and role approval are prerequisites for a public tool. [SP-API onboarding](https://developer-docs.amazon.com/sp-api/docs/onboarding-overview); [SP-API seller use cases](https://developer-docs.amazon.com/sp-api/lang-es_ES/docs/sp-api-seller-use-cases)
3. **Shopify refund leakage and return-reason report.** Read-only report that groups returns/refunds by product, discount, and stated reason; surfaces duplicate/partial refund anomalies for merchant review, never auto-denies a customer or issues/withholds money. Shopify exposes refund fields for reporting. The category has hundreds of apps, so avoid a generic returns portal. [Shopify refund query](https://shopify.dev/docs/api/admin-graphql/latest/queries/refund); [Shopify returns app category](https://apps.shopify.com/categories/orders-and-shipping-returns-and-warranty-returns-and-exchanges/all)
4. **Reseller product recall pre-listing check (Chrome extension + batch CSV/API).** Check an item identifier/name against dated official recall notices; return match/no-match/uncertain with source links, not a “safe” certification. CPSC says selling recalled products is unlawful and specifically addresses online/secondhand resellers. This directly overlaps Glacier's existing Recall Checker venture, so treat as a distribution/validation path for that venture rather than a new build. [CPSC reseller FAQ](https://www.cpsc.gov/FAQ/ResaleThrift-Stores); [CPSC online resale guidance](https://www.cpsc.gov/Business--Manufacturing/Business-Education/ResaleThrift-Stores-Information-Center/Stop-Online-Sale-of-Recalled-Products); [existing venture spec](../SPEC.md)
5. **Claims-evidence binder for product listings.** For each merchant-authored objective claim, save its source document/link, owner, product/SKU, review date, and an alert when copy changes. Flag unsupported text for human review; do not pronounce legal compliance or generate health claims. FTC guidance says advertisers need a reasonable basis for objective claims before dissemination, with stricter substantiation expectations for health/safety claims. [FTC advertising substantiation FAQ](https://www.ftc.gov/business-guidance/resources/advertising-faqs-guide-small-business); [FTC health products guidance](https://www.ftc.gov/business-guidance/resources/health-products-compliance-guidance)
6. **Shopify listing completeness / risky-field preflight.** Check required merchant-configured fields (SKU, dimensions, origin, material/care, warnings where the seller says applicable) before publish; create a review queue, not a legal verdict. Shopify's API supports product reads and scoped access, but the merchant must grant the app its requested scopes. [Shopify APIs for apps](https://shopify.dev/docs/apps/build/apis); [Shopify access scopes](https://shopify.dev/docs/api/usage/access-scopes)
7. **Etsy seller-owned listing QA from authorized API/export.** Analyze the shop owner's own title/tag/attribute completeness and broken listing references, only after Etsy approves the commercial application purpose and required API access. Etsy terms require prior application-purpose approval and prohibit automated systems/extensions from accessing or analyzing Etsy data unless Etsy expressly authorizes it. Do not scrape public Etsy listings. [Etsy API Terms](https://www.etsy.com/legal/api/); [Etsy Terms of Use](https://www.etsy.com/legal/terms-of-use)
8. **ShipStation shipment-cost variance report.** Compare a seller's own shipment-label purchase data with their own carrier invoice/export to flag weight/dimension adjustments for manual dispute review; avoid filing claims automatically. The first version can accept user-provided exports; pursue a connector only through approved partner/API terms. Existing account access does not itself establish ShipStation partner access. [ShipStation API docs](https://docs.shipstation.com/); [ShipStation partner program](https://www.shipstation.com/partners/)
9. **Multi-channel SKU/attribute normalization from seller files.** Convert the seller's own catalog export into an exception report for missing GTIN/brand/condition/category fields; later create platform-specific drafts via official APIs. Avoid copying other sellers' content or bulk publishing without review. Shopify and Amazon each document seller-authorized product/catalog APIs. [Shopify Admin API](https://shopify.dev/docs/apps/build/apis); [Amazon catalog management use case](https://developer-docs.amazon.com/sp-api/lang-es_ES/docs/sp-api-seller-use-cases)
10. **Apify actor for official state resale/secondhand dealer license records.** Search only state/local boards whose public access terms permit automation; normalize license status, expiry, source URL, and “unverifiable.” Sell per-use through Apify. Existing PH12.10 work already targets government-license lookup actors, so this is a possible source/vertical variant and must pass board-by-board terms review. Apify documents 80% of eligible actor revenue less platform usage costs; an actor's economics still depend on actual volume and compute. [Apify pricing and costs](https://docs.apify.com/platform/actors/publishing/monetize/pricing-and-costs); [PH12.10 Apify venture spec](../SPEC.md)

### 1) Amazon FBA fee/margin variance digest: five-step launch

1. **Check the account prerequisite before coding OAuth.** No Amazon seller/developer account is listed in the owner context. A pilot seller must authorize the app; public SP-API developers must register and list through Amazon's Selling Partner Appstore, while private seller apps require a Professional selling account. The first owner-only gate is to confirm a pilot seller can provide authorization and whether Benjamin can meet the applicable app-registration route. [SP-API registration overview](https://developer-docs.amazon.com/sp-api/lang-en_EN/docs/sp-api-registration-overview)
2. **Ship a CSV prototype first:** accept a seller-exported settlement/fee report plus a simple cost-of-goods CSV; produce SKU-level estimated-versus-actual margin deltas with source rows attached. No credentials or customer data leave the seller's control in this first proof.
3. **Validate fee math against official data:** use `getMyFeesEstimateForASIN` only with seller authorization and show its timestamp and “estimate, not guaranteed” caveat; reconcile actuals to report rows. [Amazon fee estimates](https://developer-docs.amazon.com/sp-api/docs/get-product-fee-estimates-asin); [fee estimate caveat](https://developer-docs.amazon.com/sp-api/docs/notification-type-values)
4. **Run a 10-seller concierge pilot** recruited through existing reseller contacts/communities with disclosure; target one output: “these SKUs had the largest unexplained margin movement.” Ask for a paid continuation before building OAuth, onboarding, or a dashboard. No unsolicited automated messages.
5. **Only if a pilot pays**, use Shopify Partner/Apify knowledge for product packaging, not as a substitute for Amazon approval: complete public app registration/review, keep read scopes minimal, then publish a weekly opt-in digest and monitor report schema changes. Amazon notes report structures can change; parser failures should stop the report and alert. [Amazon reports guide](https://developer-docs.amazon.com/sp-api/lang-it_IT/docs/reports-api-v2021-06-30-use-case-guide); [Amazon public app listing rule](https://developer-docs.amazon.com/sp-api/lang-en_EN/docs/sp-api-registration-overview)

**Owner actions:** (1) introduce/authorize one pilot seller and confirm the app-registration route; (2) approve listing and any paid hosting only after a paid pilot. The rest can be automated after merchant OAuth and source report setup.
**Estimate:** $0–$150 to validate with self-built CSV workflow; up to $300 additional for domain/hosting if OAuth requires stable public HTTPS. Estimated 2–8 weeks to first $ after a pilot; uncertain and not sourced market evidence. Keep cumulative cash below $500. Do not pay for lead lists or ads.

### 2) Shopify refund leakage / reason report: five-step launch

1. **Start with Benjamin's Shopify Partner account** and a development store; register a read-only app limited to the minimum product/order/refund scopes required. Shopify's GraphQL Admin API works with merchant-granted scopes, and the refund query supports refund reporting. [Shopify APIs](https://shopify.dev/docs/apps/build/apis); [access scopes](https://shopify.dev/docs/api/usage/access-scopes); [refund query](https://shopify.dev/docs/api/admin-graphql/latest/queries/refund)
2. **Build a one-screen exception report:** refunded amount by SKU/reason, repeated refund patterns, missing reason fields, and order/transaction source links. Do not auto-issue, delay, or deny refunds.
3. **Compare manually with 3 small-store exports** and have each seller confirm whether the “leak” flags are real. Report false positives, data gaps, and hours saved. Do not claim recoverable money until the seller verifies it.
4. **Probe the competitive gap:** review the current returns app category and ask sellers whether existing returns tools fail at post-refund reconciliation. Stop if sellers describe it as a built-in feature they already use. The category currently displays 200+ options, making broad “returns management” a poor positioning. [Shopify App Store category](https://apps.shopify.com/categories/orders-and-shipping-returns-and-warranty-returns-and-exchanges/all)
5. **Submit only after the paid pilot:** Shopify requires public App Store apps to use Shopify-provided billing, and public listings undergo app review. Offer a free one-store audit, then a narrow low-priced monthly report if merchants pay. [Shopify app billing](https://shopify.dev/docs/apps/launch/billing); [app review process](https://shopify.dev/docs/apps/launch/app-store-review/review-process)

**Owner actions:** (1) install/authorize the read-only app on a pilot shop; (2) approve App Store submission and pricing. Remaining workflow: scheduled pulls, grouping, alerts, and monthly report.
**Estimate:** $0–$150 to pilot using a dev store and exports; potentially $150–$450 for early hosting/domain and app operations, depending on chosen free-tier availability. Estimated 2–8 weeks to first $ after pilot; competition makes conversion especially uncertain. No marketing spend assumed.

### 3) Reseller recall check: five-step launch

1. **Reuse Glacier's existing Recall Checker scope** rather than create a duplicate. Use Benjamin's Chrome Web Store account and the existing venture plan; prioritize matching the exact product/model/barcode and link every hit to the official notice. [Recall Checker specification](../SPEC.md)
2. **Use official recall data and seller input only.** Read the page the reseller already has open, a barcode scan, or their uploaded inventory file; never crawl marketplaces. CPSC says resellers must know recall status and that recalled products cannot be offered for sale. [CPSC reseller FAQ](https://www.cpsc.gov/FAQ/ResaleThrift-Stores); [CPSC online resale guidance](https://www.cpsc.gov/Business--Manufacturing/Business-Education/ResaleThrift-Stores-Information-Center/Stop-Online-Sale-of-Recalled-Products)
3. **Run the project's acceptance set before listing:** 500 known-recalled and 500 known-clean products; exact identifiers first, ambiguous fuzzy matches become “uncertain”; show recall number, date, source, and remedy status. Keep the acceptance thresholds already specified in [ventures/SPEC.md](../SPEC.md).
4. **Owner reviews the first 50 recall pages and first Chrome Web Store submission** as specified in the venture plan. Do not state “safe,” “compliant,” or “no risk”; say only “no match found in [sources] as of [date]” and prompt direct verification. [Recall Checker spec](../SPEC.md); [Chrome Web Store publishing docs](https://developer.chrome.com/docs/webstore/publish)
5. **Launch a free single lookup and a small-store batch pilot**; price only after measuring false-match rate, user completion, and willingness to pay. If expanding to Amazon/Shopify, use seller authorization or customer-uploaded CSV, not page scraping.

**Owner actions:** (1) review the first 50 recall pages; (2) submit the extension listing; (3) configure test/live pricing after reviewing plan wording. These approval gates are recorded in the existing spec.
**Estimate:** $0–$100 incremental if the existing implementation and account setup hold; allow up to $250 for hosting/domain or listing-related incidentals. Estimated 2–8 weeks to first $, but Chrome review and discovery are external bottlenecks. No price/revenue promise.

## Rejected / do-not-build paths

- **Etsy-wide public listing monitor by scraping pages, browser extension, or Apify crawler:** reject. Etsy prohibits crawling/scraping in its site terms and automated systems/extensions from accessing/analyzing Etsy data absent express written authorization. Etsy API access also requires prior application-purpose approval, and commercial use remains subject to Etsy's discretion. Only pursue seller-authorized own-shop API use after approval. [Etsy Terms](https://www.etsy.com/legal/terms-of-use); [Etsy API Terms](https://www.etsy.com/legal/api/)
- **Amazon/eBay competitive price scraper or buy-box tracker based on page crawling:** reject. Use documented APIs with the seller's authorization; eBay's API license prohibits robots/spiders/scraping to access eBay content. Amazon's developer onboarding and API roles apply to integrations. [eBay API License](https://developer.ebay.com/devzone/license-agreement/api_license_agreement.pdf); [Amazon SP-API onboarding](https://developer-docs.amazon.com/sp-api/docs/onboarding-overview)
- **Automated refund/chargeback filing or “guaranteed refund recovery”:** reject at launch. This creates financial side effects, platform policy risk, false-positive customer harm, and requires seller authorization and platform-specific eligibility proof. Limit to evidence packets and reminders for owner review. Shopify exposes refund data and mutations, but access to a mutation is not a business/legal basis to execute it. [Shopify refund query](https://shopify.dev/docs/api/admin-graphql/latest/queries/refund); [Shopify refund mutation permissions](https://shopify.dev/docs/api/admin-graphql/2027-01/mutations/returnRefund)
- **AI legal/compliance certification or autogenerated health/green/safety claims:** reject. FTC guidance requires substantiation for objective claims and rigorous evidence for many health/safety claims. Build citations, change alerts, and human review queues only. [FTC small-business advertising FAQ](https://www.ftc.gov/business-guidance/resources/advertising-faqs-guide-small-business); [FTC health claims guidance](https://www.ftc.gov/business-guidance/advertising-marketing/health-claims)
- **Generic returns portal, profit dashboard, SEO listing optimizer:** deprioritize. First-party marketplace listings show extensive competition, and Shopify's returns category has hundreds of applications. Enter only with paid evidence for a narrowly defined unmet task. [Shopify returns category](https://apps.shopify.com/categories/orders-and-shipping-returns-and-warranty-returns-and-exchanges/all); [Shopify Profit Calc example](https://apps.shopify.com/profit-calc)

## Red flags and owner gates

- **No reliable willingness-to-pay evidence yet.** Public seller counts and marketplace listings cannot substitute for 10–15 interviews or a paid concierge pilot.
- **Account access is conditional.** Existing partner/developer logins do not mean app approval, data scopes, production API access, or marketplace acceptance. Amazon public app registration, Etsy purpose approval, Shopify review/billing, and Chrome review remain gatekeepers. [Amazon registration](https://developer-docs.amazon.com/sp-api/lang-en_EN/docs/sp-api-registration-overview); [Etsy API Terms](https://www.etsy.com/legal/api/); [Shopify review](https://shopify.dev/docs/apps/launch/app-store-review/review-process); [Chrome publish docs](https://developer.chrome.com/docs/webstore/publish)
- **Data access can be revoked or terms can change.** Avoid scraping; store only necessary seller data, retain source dates, respect platform retention/deletion terms, and pause automation on auth or schema errors. [Etsy API Terms](https://www.etsy.com/legal/api/); [Amazon reports guide](https://developer-docs.amazon.com/sp-api/lang-it_IT/docs/reports-api-v2021-06-30-use-case-guide)
- **Recall false negatives are safety-critical.** Every output must remain source-dated; uncertain fuzzy matches must not silently become clean. This product overlaps an existing venture, and the existing first-50 review gate stays mandatory. [CPSC reseller FAQ](https://www.cpsc.gov/FAQ/ResaleThrift-Stores); [venture spec](../SPEC.md)
- **No paid promotion or service contracts are baked into setup estimates.** Shopify public billing and Apify actor revenue share apply only after marketplace acceptance/usage. Apify's documented actor share is 80% less run platform costs. [Shopify billing](https://shopify.dev/docs/apps/launch/billing); [Apify pricing](https://docs.apify.com/platform/actors/publishing/monetize/pricing-and-costs)
- **Do not market financial/legal outcomes as guaranteed.** Amazon fee estimates are estimates; seller-specific actual fees and policies can differ. [Amazon fee caveat](https://developer-docs.amazon.com/sp-api/docs/notification-type-values)

## Recommendation

Run a no-spend, CSV-based Amazon fee/margin pilot first if Amazon developer eligibility is already in place; it is the fastest way to test whether the output is useful without finishing an app. In parallel, continue the already-authorized Recall Checker because it has a concrete public-safety rationale and existing Glacier build work. Do not start a broad Shopify returns app until interviews demonstrate a gap despite the crowded category. Treat all three time-to-cash estimates as hypotheses; ask the first pilot users to pay before expanding scope.
