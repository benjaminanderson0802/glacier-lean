### Channel requirements and evidence

- **Jobber:** Its official developer docs state the marketplace listing uses app name, developer name, app description, Manage App URL (optional for a basic listing), features/benefits, gallery images, and app logo. Review requires a Developer Center account with 2FA and an uploaded logo; review covers core function, UX, and listing details. The getting-started guide also requires OAuth callback URL, app logo (square PNG/SVG, at least 384×384, max 1 MB), gallery images, and Features & Benefits. Jobber says it may contact the developer and set up a review meeting after submission. Demand proxy: Jobber says its API ecosystem reaches 300,000+ home-service pros. [Listing details](https://developer.getjobber.com/docs/publishing_your_app/app_listing_details/), [review process](https://developer.getjobber.com/docs/publishing_your_app/app_review_process/), [getting started](https://developer.getjobber.com/docs/getting_started/), [Jobber developer overview](https://developer.getjobber.com/docs/).
- **Shopify:** Public apps go through technical and listing review. Shopify's requirements require factual, accurate descriptions/tags, clear app functionality, supported UI, truthful listing claims, and appropriate permissions/geography; app must meet review-page requirements before submission. Demand proxy: Shopify reports millions of businesses, 21,000+ apps and 3 in 4 merchants using apps. [App Store requirements](https://shopify.dev/docs/apps/launch/shopify-app-store/app-store-requirements), [review process](https://shopify.dev/docs/apps/launch/app-store-review/review-process), [Shopify App Store principles and audience figures](https://www.shopify.com/about/app-store-principles).
- **Etsy:** Best treated here as the makers' storefront marketplace rather than an app catalog. Etsy says a personal API app is limited-scale; apps for broader commercial use must request commercial access, which is reviewed more deeply. API use is governed by Etsy's API terms and can be reviewed/audited. Etsy requires seller registration and a policy-compliant handmade, vintage, or craft-supply item; its listing form has seven tabs: photos/video, category, item details, item options, pricing/shipping, how it is made, and settings. Validate the live form and fees before preparing an actual product listing. Demand proxy: 86.5M active buyers and 5.6M active sellers at 2025 year-end. [Etsy developer portal](https://www.etsy.com/developers/), [API terms](https://www.etsy.com/legal/api/), [how to create an Etsy listing](https://help.etsy.com/hc/en-us/articles/115015628707-How-to-Create-a-Listing), [Creativity Standards](https://www.etsy.com/legal/creativity/), [2025 annual report](https://investors.etsy.com/sec-filings/all-sec-filings/content/0001370637-26-000019/etsy-20251231.htm).

### Method and limits

On **2026-10-11**, the unauthenticated public endpoint `https://api.apify.com/v2/store?search=...&limit=1000&sortBy=popularity` was queried for each topic. Apify documents this endpoint as public/no-token and supports keyword search across title, name, description, username, and README. The table gives the API's `total` for the displayed query, not a count of exact substitutes; overlapping results, loose text matches, stale Actors, and pagination explain why counts are only directional. `30d users / lifetime runs` are from example top-ranked related results, not aggregate category demand. Apify Store metrics are marketplace activity proxies, not revenue or willingness-to-pay evidence. Ideas below are not claims that no competitor exists.

Apify's publishing requirements are concrete: public Actor README/detail page; display info (logo and description); monetization setup; sample output; output schema (optionally dataset/key-value/live-view schemas); and declared Actor permission level. The Actor then must be published from the Console and verified on Store. [Store API docs](https://docs.apify.com/api/v2/store), [publish Actor](https://docs.apify.com/actors/publishing/publish), [Store marketplace](https://apify.com/store).

### Recommended pilot order

1. **DIBBS RFQ Change Feed**: low observed Store result count and a naturally recurring public-data workflow. Validate official source stability and a free sample before any paid model is chosen.
2. **FSIS Recall Monitor or OpenEI Tariff Change Watch**: choose one after checking source freshness, exact Actor overlap, and a small user task. Both appear more focused than broad web scraping.
3. Keep the OSHA and utility Actors as secondary candidates because they overlap current Glacier ventures and can turn into compliance or rate claims if not tightly scoped.
4. Defer USAspending/SAM combination and generic SEC/Census products until a niche workflow differentiates them from the larger Store search set.

**Pricing posture:** No price is approved by this research. If an Actor is later built, compare the platform's current monetization options and direct substitutes, then propose a low-friction free sample or low-cost run-based price for owner approval. Do not incur paid API, proxy, or marketplace costs; all proposed government data sources above are public agency endpoints/data pages, but API keys and rate limits may still apply.

## Source and market-data cautions

- Official marketplace audience figures are platform-reported reach, not an estimate of this venture's addressable buyers.
- Store API keyword totals are search-return counts, not unique competitor counts or proof that an Actor has active paying customers. Re-run the same query and inspect result identities before committing build time.
- Public government data can have stale, partial, access-controlled, or source-specific terms. The Actor must preserve retrieval timestamps/source URLs and follow each API's terms and rate limits.
- Marketplace reviews, API/commercial access, account setup, pricing choice, and publication remain owner decisions. This plan authorizes none of them.
