# R-APIFYGAPS — Apify Store gap scan

**Research snapshot:** 2026-10-10 (UTC). **Owner context:** Benjamin already has Apify, Shopify Partner, Jobber developer, Chrome Web Store accounts; SAM.gov registration is in progress. Glacier is available for local scheduled checks and internal canaries.

## Recommendation in one paragraph

Prioritize narrowly scoped, official-source data products that normalize a government download/API into a predictable schema, with source URL/date and explicit “unverifiable” behavior. Best first experiment: Alabama contractor-license roster validation, using the board’s published roster or an expressly authorized export (no automated browsing until the board confirms permission). Then test a Census Building Permits API change-feed and an FDIC BankFind API normalizer. Do not mistake Apify Store search result counts for customer demand: the public Store API exposes total runs, recent public runs, monthly users, ratings and review counts, but the searches below return broad, overlapping relevance results. A run is not necessarily a paying run or external user.

## Method and interpretation

I queried the public Apify Store API on 2026-10-10 using `GET https://api.apify.com/v2/store?search=<phrase>&limit=1000&sortBy=popularity`; `data.total` is the Store search result count (not necessarily unique relevant competitors). For selected listings I recorded lifetime `totalRuns`, public run total in the preceding 30 days, `totalUsers30Days`, rating and review count. Search results include false positives and near-duplicates; counts are directional, not market size. The API documents these fields and search behavior: [Apify Store API](https://docs.apify.com/api/v2/store-get). A Store listing’s run counts alone do not prove revenue; Apify documents its separate pay-per-event model and platform costs [here](https://docs.apify.com/actors/publishing/monetize) and its current Free plan as $0 with $5 usage credit and $0.20/CU [here](https://apify.com/pricing).

**Owner action assumption:** no spend is needed to prototype against public data or use the existing Apify free-plan credit, but live compute after credits can cost money. Set an explicit small usage cap; any paid account change remains an owner decision. The report estimates time to first dollar as a planning range, not a guarantee.

## Scored top 3

Scoring is 1–5. **Demand:** observed evidence strength (Store activity and/or official dataset usage); **competition:** 5 means few relevant competitors, 1 means crowded; **setup:** 5 means cheapest/easiest; **automation:** 5 means minimal recurring human work; **legal:** 5 means lower source/legal risk if the stated access method is followed; **time:** 5 means shortest plausible time to first revenue. Demand is an evidence score, not a revenue forecast. Scores intentionally discount weak Store counts and any need for terms permission.

### 1) Alabama contractor roster / status verifier

**Why it ranks first.** The Store search found six Alabama contractor-license listings, and the leading one had 462 total runs/41 public runs in the last 30 days/6 monthly users. Alabama’s board directs consumers to a license search and reports 10,594 current licensees. The board also publishes an annual roster under state law. That supports a practical, state-specific data normalization test; it does not establish meaningful paid demand. [Board homepage](https://genconbd.alabama.gov/) [Roster statute](https://genconbd.alabama.gov/Rules_%20Regulations_.pdf) [Store snapshot query](https://api.apify.com/v2/store?search=Alabama%20contractor%20license&limit=1000&sortBy=popularity)

**Concrete five-step launch plan (1–2 owner-only actions).**

1. Use the existing Apify developer account to make an unpublished Actor that ingests the board’s official roster/export and a batch of user-supplied license numbers; return literal board status, expiry, source URL/file date, and `unverifiable` when the roster is absent or stale. Keep it separate from any automatic webpage access until the board confirms that method is permitted. [Board roster/search](https://genconbd.alabama.gov/) [Alabama board rules and roster statute](https://genconbd.alabama.gov/Rules_%20Regulations_.pdf)
2. Use Glacier’s existing Apify data-tool workflow as the scheduled canary: three official records, a stale-file test, a no-match test and a source-change alert. Reuse the verified Mississippi Actor pattern as an internal test reference, not as proof the Alabama source behaves the same way. [Current Mississippi proof](../apify-tools/PROOF.md)
3. Compare the output independently with the board’s official records and write source-date + rate/volume behavior into Actor docs. Fail closed on identity/status mismatch; never say “legitimate” or guarantee insurance/quality. [Board homepage](https://genconbd.alabama.gov/)
4. Create a concise Store listing with one free sample run and a capped pay-per-event trial price; Apify says pay-per-event creators receive 80% of event revenue before the Actor’s platform costs, so price above compute cost. [Apify monetization](https://docs.apify.com/actors/publishing/monetize) [Apify pricing](https://apify.com/pricing)
5. **Owner action 1:** approve/submit the first listing after reviewing source permission and output wording. **Owner action 2 (only if required):** request the official roster or written automated-access permission from the board. Do not publish if the only viable source path is prohibited or unapproved. [Alabama board rules and roster statute](https://genconbd.alabama.gov/Rules_%20Regulations_.pdf)

**Red flags.** State licensing regimes split among boards and license classes; Alabama’s count is only one board’s scope. A roster snapshot may lag status changes; label its as-of date and never imply real-time verification. Confirm that commercial republication and automated access are allowed; public availability alone does not prove either. A name match is not identity proof. [Alabama board](https://genconbd.alabama.gov/) [Alabama board rules and roster statute](https://genconbd.alabama.gov/Rules_%20Regulations_.pdf)

### 2) Census BPS change feed

**Why it ranks.** The exact Store search surfaced one matching Actor, with only 49 total runs and 1 monthly user; competition looks low, while direct payment demand remains unvalidated. Census publishes monthly/YTD/annual values across states, counties and permit-issuing places and makes official API/data access available. This is a good near-zero-cost validation experiment, not a proven business. [Census BPS](https://www.census.gov/construction/bps/index.html) [Census API](https://www.census.gov/data/developers/data-sets.html) [Store snapshot query](https://api.apify.com/v2/store?search=Census%20building%20permits%20API&limit=1000&sortBy=popularity)

**Concrete five-step launch plan (1–2 owner-only actions).**

1. Use the existing Apify account to build a small API-only Actor for a user-selected geography and period; emit normalized units, source table, vintage, revision flag and retrieval timestamp. Use Census BPS / API endpoints only. [BPS](https://www.census.gov/construction/bps/index.html) [Census API](https://www.census.gov/data/developers/data-sets.html)
2. Add a Glacier monthly schedule and independent comparison against Census’s published annual/monthly tables; alert on schema, vintage or revision changes. [BPS methodology/release details](https://www.census.gov/construction/bps/methodology.html)
3. Create one concrete output—county/permit-place monthly delta JSON/CSV—with no forecast or “investment signal” claims. Cite the Census vintage inside each record. [BPS](https://www.census.gov/construction/bps/index.html)
4. Ask five construction-data consumers already reachable through the owner’s Jobber developer or Shopify Partner networks to try the sample; use existing accounts for conversations and channel discovery only, not as a claim of endorsement or partnership. Keep the sample free and measure repeat runs before expanding.
5. **Owner action 1:** approve Store listing only if at least two independent users request a repeatable output. If not, leave it as an internal Glacier feed and stop. Store listing uses Apify’s pay-per-event option; platform costs must be covered in price. [Apify monetization](https://docs.apify.com/actors/publishing/monetize)

**Red flags.** The source already provides data at several geographic/time grains; a thin wrapper may add too little value. “Low competition” based on one search result can also mean no buyer demand. Census revisions and imputation mean snapshots can change; preserve vintage and source metadata. [BPS methodology](https://www.census.gov/construction/bps/methodology.html)

### 3) FDIC BankFind normalizer

**Why it ranks.** Store search returned 35 results, with the top direct listing at 397 total runs/27 public runs in 30 days and the next two at 186/215 total runs. This is small but recurring usage; the official FDIC BankFind Suite offers API/data resources. A normalized output can be tested cheaply, but demand is not strong enough to justify a standalone product without buyer evidence. [FDIC BankFind](https://banks.data.fdic.gov/bankfind-suite/) [Store snapshot query](https://api.apify.com/v2/store?search=FDIC%20API&limit=1000&sortBy=popularity)

**Concrete five-step launch plan (1–2 owner-only actions).**

1. Use existing Apify account to implement an API-only Actor for one defined use case: query an institution by FDIC certificate/active status, or retrieve a date-stamped selected financial series. Preserve source fields and update date. [FDIC BankFind](https://banks.data.fdic.gov/bankfind-suite/)
2. Build a Glacier daily/weekly canary against several fixed institutions and compare IDs, status and selected figures with the FDIC result pages. Do not infer creditworthiness or failure risk.
3. Export a stable JSON/CSV schema and document missing values, effective dates and source. Include a clear “data is not a credit, investment, or regulatory determination” boundary.
4. Use the existing Shopify Partner account only to identify whether an appropriate financial-data app channel exists; validate three prospective users with a sample before investing in the listing. No Shopify app build is recommended at this stage.
5. **Owner action 1:** approve publication after buyer validation and a costed event price; otherwise retain as internal data plumbing. Apify’s current free tier includes limited usage and paid compute is $0.20/CU, so keep compute bounded. [Apify pricing](https://apify.com/pricing) [Apify monetization](https://docs.apify.com/actors/publishing/monetize)

**Red flags.** Official data can still be stale, revised or misinterpreted; never convert a record into financial advice, bank safety conclusions or a compliance clearance. Existing official pages already solve basic lookup, so the value must be repeatable normalization/deltas for a specific workflow. [FDIC BankFind](https://banks.data.fdic.gov/bankfind-suite/)

## Reject / defer list and red flags

- **Reject scraping SAM.gov pages.** SAM terms explicitly ban automated scraping/data gathering and say not to use a SAM login for bots. Use only public official APIs/exports within their key, account, sensitivity and display limits; never expose or share Benjamin’s individual key. [SAM.gov terms](https://sam.gov/about/terms-of-use) [Public opportunities API](https://open.gsa.gov/api/get-opportunities-public-api/)
- **Defer SAM exclusions as a paid compliance checker.** Low Store competition is outweighed by API request limits and severe false-negative consequences. It would need per-customer credentials or a vetted public extract, point-in-time semantics, reconciliation and explicit “screening aid only” language. [GSA exclusions API](https://open.gsa.gov/api/exclusions-api/)
- **Reject DIBBS UI scraping/login automation.** Store activity is comparatively high, but DIBBS is a DoD information system with a warning/consent notice; no evidence here establishes that unattended commercial scraping is authorized. Use an official download, written permission, or leave it alone. Never submit quotes or fetch export-controlled technical data. [DIBBS warning](https://www.dibbs.bsm.dla.mil/dodwarning.aspx?goto=%2Fsolicitations%2Fchoose) [DLA description](https://www.dla.mil/Acquisition/Oers/eProcurement/)
- **Reject generic SEC EDGAR scraper.** Crowded Store search and meaningful access-policy obligations; a narrow API-first structured feed would need an explicit buyer before work. SEC guidance warns against unclassified bots and applies rate limits. [SEC access FAQ](https://www.sec.gov/files/about/webmaster-faq.htm)
- **Do not turn openFDA food-enforcement records into public recall alerts or lifecycle status.** FDA expressly disallows those uses for that feed and warns that records are not validated as a definitive live safety state. Keep recall-checker work within the venture spec and its separate source/quality rules. [FDA food enforcement](https://open.fda.gov/apis/food/enforcement/)
- **Never assume public record means unrestricted reuse.** Confirm source terms, bulk-download license/notice, privacy restrictions and commercial republication before a venture collects, republishes, enriches or contacts people. Avoid sources whose terms prohibit the proposed automation; do not use proxies, CAPTCHA solving, authenticated consumer sessions, or account-key sharing as workarounds. [SAM terms example](https://sam.gov/about/terms-of-use) [Venture Build Spec](../SPEC.md)
- **Income is uncertain.** Store runs/users/reviews are platform usage signals only; no reliable public source gives category-level conversion or creator earnings. Apify handles marketplace billing for eligible Actors, but profit is event revenue less platform costs and does not guarantee discovery or sales. [Apify monetization](https://docs.apify.com/actors/publishing/monetize) [PPE economics](https://help.apify.com/en/articles/12800725-ship-your-actor-and-get-paid)
