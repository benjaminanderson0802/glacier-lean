# Freight claim intake

ShipStation API alternative: place a Shipments or Orders export (`.csv`) directly in this folder. The daily shipment check uses the newest CSV if API access is not enabled or the API read fails. To select a file directly, run `python ventures/freight-claims/scripts/claims.py watch --csv /path/to/export.csv`. The report lists skipped row numbers and reasons. Keep only customer shipment data needed for local claim preparation here; never include API keys.

For a customer-facing evidence and deadline checklist, use [CUSTOMER-INTAKE.md](CUSTOMER-INTAKE.md). To generate packet drafts directly from a CSV, provide a separate JSON list with one customer-confirmed entry per exception shipment, keyed by `shipment_id`, then run `claims.py prepare-csv --csv PATH --input PATH --output-dir PATH`. Include `shipment_type` (`damage` or `lost`) and the date anchor requested by that carrier template. If issue type, service, destination, or date is unclear, the packet will not guess a deadline. CSV rows supply shipment facts only; they do not confirm the loss, damaged items, value, or carrier terms. A missing customer entry stays in `needs_customer_intake` and no packet is fabricated for it.

Place the customer-confirmed intake record at `$GLACIER_HOME/ventures/freight-claims/incoming/claim-intake.json`. Put its supporting files in `$GLACIER_HOME/ventures/freight-claims/incoming/customer-uploads/` and reference each absolute file path in the record. The venture currently uses a local on-device handoff; it does not expose a hosted upload link.

Required document keys are `delivery_receipt`, `photos`, `commercial_invoice`, and `bill_of_lading`. Each may be one file path or a list of paths. For receipt tracking, `incoming/receipt.json` requires `claim_id`, `carrier_received_date`, `reference`, and `confirmation_document`; add `carrier` and a customer-confirmed `carrier_response_due_on` if the carrier supplied a promised response date. This date is tracked locally and is not sent to the carrier. Do not include credentials in an intake file.
