# Freight claims

Freight claims prepares source-linked packets for possible lost, damaged, or short pallet shipments. It reads ShipStation shipment records, flags possible exceptions for the shipper to confirm, reads the bill of lading, invoice, delivery receipt, and photos with Glacier's shared document reader, and keeps carrier response deadlines on a local timeline.

The packet claims only the invoice value of items the shipper marks as damaged and confirms against the invoice. A separate liability estimate is shown only when the shipper confirms the carrier-terms URL, effective date, shipment weight, and per-pound limit. Those figures are preparation aids; the customer reviews them and decides what to claim. Missing documents, uncertain reader fields, unclear insurance coverage, and conflicting evidence stay visible.

Glacier prepares an email draft and attachment list but does not contact a carrier, submit a claim, sign for a shipper, invoice a customer, or charge a payment method. A signature request uses only an authorization document supplied and approved by the owner; the shipper signs through the shared customer block. A shipper reviews and sends its claim. The customer then provides the carrier receipt confirmation; only then does the deadline tracker start the 30- and 120-day reminders. After recovery, the invoice draft calculates the agreed 20–30% share and waits for owner review.

ShipStation API access is read-only and starts disabled. ShipStation requires the Gold plan or higher for API access. Use the [ShipStation API V2 authentication guide](https://docs.shipstation.com/authentication) to check API availability in the account's API Settings and generate its key; read the current [usage and rate limits](https://docs.shipstation.com/rate-limits) before enabling. Save the key in Glacier Settings > Secrets, then create `$GLACIER_HOME/ventures/freight-claims/shipstation-enabled.json` with `{"approved": true}`. One daily run is bounded to 20 shipment-page requests and 100 label-tracking requests; compare that maximum with account usage and any account-specific limits. Tracking calls use ShipStation's documented [label tracking endpoint](https://docs.shipstation.com/tracking).

If the account cannot use the API, download a ShipStation **Shipments** or **Orders** CSV export and place it in `$GLACIER_HOME/ventures/freight-claims/incoming/`. The daily flow automatically reads the newest `.csv` there if the API is not enabled or a read fails. You can select a particular export with `python ventures/freight-claims/scripts/claims.py watch --csv /path/to/export.csv`. The report records the source file and any skipped rows. Extra columns are ignored; rows without a tracking number are skipped with a reason. CSV intake is local and read-only. No account, paid service, or live transaction is created by this venture. The shared customer block's Stripe support remains test-mode only.

Carrier-specific packet guidance now covers UPS, FedEx, USPS, and LTL/Carmack review: filing window and date anchor, evidence checklist, official sources, and response-date tracking. The printable packet checklists are in [carrier-templates](carrier-templates/README.md). Calculated dates are estimates to verify against the exact service and shipment terms. USPS lost-mail deadlines require a service lookup; unknown carriers do not get a guessed deadline. LTL response milestones apply only where 49 CFR Part 370 governs. See the [customer intake checklist](incoming/CUSTOMER-INTAKE.md) for the customer-facing handoff and current source links.

## Owner step

The ShipStation channel is not a confirmed public app listing. ShipStation's official route is an integration-partner inquiry; eligibility, listing review, and commercial terms are not published. The prepared copy and exact inquiry steps are in [OWNER-STEPS.md](OWNER-STEPS.md) and [the partner package](listing/SHIPSTATION-PARTNER-PACKAGE.md). Submit the inquiry only if the written terms and any fees are acceptable. A paid integration partnership is not approved by this preparation.

In the same setup sitting, connect ShipStation read-only only if the current plan and quota fit without extra spending, or put its Shipments/Orders CSV export in the local incoming folder; then review the first ten distinct packets against their sources, customer confirmations, exact carrier terms, and insurance status. For each actual claim, the shipper confirms, signs and files with the carrier, then records its receipt and responses and decides settlements. The owner reviews any invoice draft before sending. Glacier does not sign, file, contact carriers, send invoices, or charge payments.

## Run locally

```sh
~/w/glacier-lean/.venv/bin/python -m ventures.install_all --dry-run --only freight-claims
~/w/glacier-lean/.venv/bin/python ventures/freight-claims/scripts/claims.py watch
~/w/glacier-lean/.venv/bin/python ventures/freight-claims/scripts/claims.py prepare-csv --csv /path/to/shipstation-export.csv --input /path/to/customer-claim-intake.json
~/w/glacier-lean/.venv/bin/python -m pytest -q ventures/freight-claims/tests
```

Place a ShipStation export at `$GLACIER_HOME/ventures/freight-claims/incoming/shipstation-shipments.csv` and customer-confirmed claim data at `$GLACIER_HOME/ventures/freight-claims/incoming/claim-intake.json`; place documents in `$GLACIER_HOME/ventures/freight-claims/incoming/customer-uploads/` and list their absolute paths. See [incoming/README.md](incoming/README.md) for the exact file handoff. This local folder is not a hosted customer upload link. The installed prepare flow joins the CSV to the separate intake, then prepares source-linked packet drafts. Use a list of records or one record with `shipment`, `damaged_items`, `documents`, `carrier_terms`, and `separate_insurance`. Set `customer_confirmed: true` on each damaged item only after the shipper checks its quantity and price against the commercial invoice. Set `carrier_terms.customer_confirmed: true` only after the shipper confirms the published terms URL, effective date, and liability limit. For a covered shipment, set `customer_requests_claim` only after the shipper explicitly asks for a carrier claim. Do not put carrier credentials in intake JSON. For an authorization request, use an owner-approved document at `incoming/owner-approved-authorization.pdf` and signer details at `incoming/signer.json`; the generated local link is not shared off-device automatically. After the shipper submits, place `claim_id`, `carrier_received_date`, `reference`, and `confirmation_document` in `incoming/receipt.json` and run the carrier receipt flow.
For a settlement, put the carrier offer in `$GLACIER_HOME/ventures/freight-claims/incoming/settlement-offer.json` with `claim_id`, `amount`, `full_release: true`, and the shipper's explicit `customer_decision` (`accept` or `decline`). Run `freight-settlement-decision`; the flow displays the offer, requires a Glacier approval, and writes the recorded choice. The workflow never accepts an offer on the customer's behalf.
