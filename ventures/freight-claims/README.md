# Freight claims

Freight claims prepares source-linked packets for possible lost, damaged, or short pallet shipments. It reads ShipStation shipment records, flags possible exceptions for the shipper to confirm, reads the bill of lading, invoice, delivery receipt, and photos with Glacier's shared document reader, and keeps carrier response deadlines on a local timeline.

The packet claims only the invoice value of items the shipper marks as damaged and confirms against the invoice. A separate liability estimate is shown only when the shipper confirms the carrier-terms URL, effective date, shipment weight, and per-pound limit. Those figures are preparation aids; the customer reviews them and decides what to claim. Missing documents, uncertain reader fields, unclear insurance coverage, and conflicting evidence stay visible.

Glacier prepares an email draft and attachment list but does not contact a carrier, submit a claim, sign for a shipper, invoice a customer, or charge a payment method. A signature request uses only an authorization document supplied and approved by the owner; the shipper signs through the shared customer block. A shipper reviews and sends its claim. The customer then provides the carrier receipt confirmation; only then does the deadline tracker start the 30- and 120-day reminders. After recovery, the invoice draft calculates the agreed 20–30% share and waits for owner review.

ShipStation API access is read-only and starts disabled. ShipStation requires the Gold plan or higher for API access. Use the [ShipStation API V2 authentication guide](https://docs.shipstation.com/authentication) to check API availability in the account's API Settings and generate its key; read the current [usage and rate limits](https://docs.shipstation.com/rate-limits) before enabling. Save the key in Glacier Settings > Secrets, then create `$GLACIER_HOME/ventures/freight-claims/shipstation-enabled.json` with `{"approved": true}`. One daily run is bounded to 20 shipment-page requests and 100 label-tracking requests; compare that maximum with account usage and any account-specific limits. Tracking calls use ShipStation's documented [label tracking endpoint](https://docs.shipstation.com/tracking).

If the account cannot use the API, download a ShipStation **Shipments** or **Orders** CSV export and place it in `$GLACIER_HOME/ventures/freight-claims/incoming/`. The daily flow automatically reads the newest `.csv` there if the API is not enabled or a read fails. You can select a particular export with `python ventures/freight-claims/scripts/claims.py watch --csv /path/to/export.csv`. The report records the source file and any skipped rows. Extra columns are ignored; rows without a tracking number are skipped with a reason. CSV intake is local and read-only. No account, paid service, or live transaction is created by this venture. The shared customer block's Stripe support remains test-mode only.

## Your steps

1. Pick API or CSV. For API access, check the Gold plan requirement and limits in [ShipStation API Settings](https://docs.shipstation.com/authentication) and its [usage guide](https://docs.shipstation.com/rate-limits), save the key in Glacier Secrets, then enable polling. Otherwise, put a Shipments or Orders CSV export in `incoming/`. Review the first shipment list either way.
2. Review and approve the first ten distinct claim packets against their source documents, carrier terms, and insurance status. Each approval ID is recorded in a local review ledger; later packets still require shipper review.
3. Have the shipper provide or sign owner-approved authorization, confirm the claim details, and send the draft. Record the carrier receipt and any recovery. For a full-release offer, the shipper explicitly accepts or declines; acceptance closes the claim, while declining keeps it open. Approve any invoice draft before it is sent.
