# To build a project with a team

Build is an interview about the whole project. It keeps asking about your goal, audience, what “done” means, must-haves, limits, examples and risks until you confirm that it understands. It then prepares a written spec. Review and approve the spec before Build prepares a work plan and the smallest team that can do the work.

## To review the team

The team has a lead to coordinate tasks, builders to make the changes, and an independent evaluator. Only the evaluator can mark a feature as passing, and it must attach evidence. A researcher or reviewer can be added when useful. The planner creates the plan and then steps away; it never joins the team or does its work.

Review the tasks, roles and checks before approving the plan. That approval starts the team in Automations. It runs until its planned work is complete, waiting only when a task needs your approval. Local models work on one task at a time; other supported routes can run several tasks at once when the plan allows it.

## To manage a team

Use Pause to let current work finish and wait before starting more. Use Stop to end the run. Resume continues an approved plan from its saved progress. A team does not call a feature done because a builder says it is done: the evaluator must pass it with evidence, and the final checks must pass too.

If work stalls, the team retries up to three times, then tries a shorter plan up to twice. If it is still stuck, Glacier saves a claim with the attempts and evidence so the issue can be reviewed. Check Home for work waiting on you.
