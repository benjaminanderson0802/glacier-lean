# To handle a problem

If a run fails, Glacier can send a plain-language alert to the destinations configured for that flow or installation. Open the run details and read which step failed and what its output says. A failed step may need attention even if earlier steps succeeded.

Some steps can retry a limited number of times. A retry is another attempt; it does not prove the result is correct. Follow the run's checks to see whether its result was verified.

## File or review a claim

A claim records a problem, missing ability, or unclear requirement with evidence. File one when you cannot safely continue, when a tool is missing, or when a problem needs someone else's decision. Include what you expected, what happened, and the useful error text. Do not include passwords or secret values.

Claims can be investigated, sent to a specialist, or brought to the owner for a decision. A claim should be closed only after there is evidence for its resolution. Check [Checks and trust](02-checks-and-trust.md) to understand verification.

## Safe next steps

Do not keep repeating an action that gives the same failure. Avoid approving a repair or external action you do not understand. Keep the run details and error message with your claim so the next person can investigate it.
