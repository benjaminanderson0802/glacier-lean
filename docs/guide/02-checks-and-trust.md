# To check whether work is done

An AI helper can sound certain and still be wrong. A check gives you a separate way to decide whether the result meets the goal. Choose the check before the work begins, so the worker cannot quietly change what counts as success.

Checks can run a command, compare a file with a required shape, ask a separate reviewer to judge written rules, or ask you to approve the result. A flow can have more than one check. Required checks must all pass for the run to be marked verified.

**Verified** means the run finished and its required checks passed. If there are no checks, or the run is not finished, it is not marked verified. Verification tells you that the chosen checks passed; it does not promise that every possible mistake was found. Read the check and its evidence before relying on important work.

Keep checks separate from the worker's work. The verifier uses the saved checks from when the run started. A worker must not change or skip its own checks.

## What is a claim?

A claim is a saved report of a problem, missing ability, or unclear instruction. It includes a short summary and evidence, and can be reviewed as someone investigates it. Claims help keep a problem visible until there is a fix or a decision. See [When something breaks](05-when-something-breaks.md).
